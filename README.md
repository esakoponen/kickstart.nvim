# Neovim configuration

A personal Neovim configuration in a single, commented `init.lua`. It started as a fork of
[kickstart.nvim](https://github.com/nvim-lua/kickstart.nvim) and has since been rewritten around
Neovim's built-in package manager, `vim.pack`.

The same files run unchanged on WSL (Ubuntu), Arch Linux and Windows 11. Linux is the main
platform; the few platform differences are handled inside `init.lua`.

## Requirements

- **Neovim 0.13 nightly** on every machine. Stable releases lack APIs this config uses. Ways to
  install it: [INSTALLING-NEOVIM.md](INSTALLING-NEOVIM.md).
- `git`, `curl`, `unzip`, a C compiler (treesitter builds its parsers), `fzf`, `ripgrep` and `fd`.
  Package lists for Ubuntu, WSL and Arch: [LINUX-SETUP.md](LINUX-SETUP.md).
- The toolchain of each language you work in, for its language server:
  [LANGUAGE-RUNTIMES.md](LANGUAGE-RUNTIMES.md).
- No Nerd Font: icons are ASCII letters.

## Install

    # Linux and WSL
    git clone <this-repo> ~/.config/nvim

    # Windows (PowerShell)
    git clone <this-repo> "$env:LOCALAPPDATA\nvim"

Start `nvim`. vim.pack lists the plugins it is about to install; answer **Yes**. Mason then installs
the language servers, formatters, linters and debug adapters in the background. When it has
finished, `:checkhealth` (or `<leader>rh`) reports anything still missing.

To update: `<leader>rp` (`:packupdate`) for plugins, `:MasonToolsUpdate` for Mason's tools.

## What it does

- **Languages**: language servers for C, C++, Python, Ruby and Rails, Elixir and HEEx, C#, Rust,
  Lua, HTML, CSS, JavaScript, TypeScript and Bicep, plus Erlang on Linux and WSL. Formatting on
  demand with `<leader>f`; linters run on save.
- **Debugging and tests**: nvim-dap for Python, C, C++, Rust, C# and Elixir; vim-test runs the
  nearest test, the file or the suite in any of those languages.
- **Finding things**: fzf-lua for files, grep, symbols, buffers, git and help; oil.nvim edits
  directories as text.
- **Git**: gitsigns for hunks, blame and staging; a three-pane `git mergetool` view whose side
  panes show each conflicting line's commit and author; commit messages wrap at 72 columns.
- **Markdown**: a live browser preview that renders Mermaid diagrams and KaTeX maths, offline.
- **Keyboard**: designed for a Finnish layout, where `[` and `]` need AltGr: `ö` and `ä` stand in
  for them.

## Keybinding cheatsheet

The `nvim-keybindings-v<n>.svg` files are 3840×2400 desktop wallpapers listing the keys; the
highest `<n>` is the current one. From v4 on they are generated by a script, never edited by hand.
To make the next version, run this from the repository root, with `<n>` one higher than the newest
file:

    python cheatsheet/generate.py nvim-keybindings-v<n>.svg

Three things decide the result, and the same three always give a byte-identical SVG:

| File | What it decides |
|---|---|
| [`cheatsheet/keybindings.json`](cheatsheet/keybindings.json) | the content: the panels, their order, and every key, description and note |
| [`cheatsheet/generate.py`](cheatsheet/generate.py) | the page size, layout, colours and fonts |
| the fonts Segoe UI and Cascadia Mono, from Windows | the text widths, and so the scale and every position |

The script places the panels in the four columns itself, keeping their order from the JSON, and
shrinks every size by one factor until all panels fit above the taskbar.

**Changing a key:** update [KEYBINDINGS.md](KEYBINDINGS.md), make `keybindings.json` match,
generate the next version, and commit the JSON and the new SVG together. Earlier versions stay as
they are; v1 to v3 were made before the script and cannot be regenerated.

**The JSON.** `panels` lists the panels in reading order. Each has a `title`, an `accent` colour
(`blue`, `cyan`, `teal`, `purple`, `sky` or `rose`), an optional `hint` shown at its top right, and
`rows` of four kinds:

| Row | Drawn as |
|---|---|
| `{"keys": "<leader>sf / <leader>s.", "desc": "…", "note": "…"}` | keycaps, a description and an optional dim note; ` / ` separates alternative keys |
| `{"section": "Buffers", "keys": "<leader>S"}` | a sub-heading, with optional keys after it |
| `{"comment": "…"}` | a dim line of its own |
| `{"command": "git mergetool", "note": "…"}` | a shell command, shown after `$`; one starting with `:` is shown as an Ex command |

`<leader>` and `<Space>` are both drawn as the ␣ symbol. In keycaps, modifiers (`C-` Ctrl, `S-`
Shift, `A-` or `M-` Alt) and named keys (`Tab`, `Esc`, `Enter`, `Space`, `BS`, `Del`, `F1` to
`F12`) are drawn in the ␣ symbol's colour, and typed characters in white, so `C-c` (Ctrl+c) never
reads like `C` (Shift+c).

**Requirements:** Python 3 and Pillow (`pip install pillow`; on Ubuntu, `sudo apt install
python3-pil`). The fonts are read from `C:\Windows\Fonts`, or `/mnt/c/Windows/Fonts` under WSL. On
another machine, copy `CascadiaMono.ttf`, `segoeui.ttf`, `segoeuii.ttf` and `seguisb.ttf` into a
directory and pass `--fonts <dir>`.

**A PNG for the wallpaper** (optional; PNGs are not committed). From PowerShell:

    & "C:\Program Files\Google\Chrome\Application\chrome.exe" --headless --disable-gpu --hide-scrollbars `
      --force-device-scale-factor=1 --window-size=3840,2400 `
      --screenshot="$PWD\nvim-keybindings-v<n>.png" "$PWD\nvim-keybindings-v<n>.svg"

## Files from kickstart.nvim

`lua/kickstart/`, `lua/custom/` and `doc/kickstart.txt` are upstream files, kept so that merging
from kickstart.nvim stays simple. `init.lua` loads none of them; only `:checkhealth` still runs
kickstart's basic check from `lua/kickstart/health.lua`. kickstart.nvim's MIT licence is in
[LICENSE.md](LICENSE.md).
